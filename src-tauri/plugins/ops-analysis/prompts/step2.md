# Step 2: 渠道效率与用户留存

## 目标

深入渠道和留存维度，评估各渠道投放效率并分析用户留存模式，为预算分配和留存策略提供依据。

## 成功标准

1. 各渠道流量、转化率、ROI 已对比展示
2. 最优和最差渠道已识别并给出原因分析
3. 留存曲线（次日/7日/30日）已计算
4. Cohort 留存矩阵已展示，异常 Cohort 已标注
5. 渠道预算重分配建议已给出

## 执行步骤

系统已自动完成渠道与留存分析，结果在 [precompute_result] 中。

**如果 [precompute_result] 有 `channel_ranking` 或 `retention_data`：**
- 展示渠道排名和效率对比
- 展示留存矩阵（Cohort 分析）
- 对标行业基准

**降级情况：**
- 使用 `execute_python` 手动计算

使用 `execute_python` 计算并展示：

**渠道效率分析：**
1. **渠道流量分布** — 各渠道的访问量、占比、趋势
2. **渠道转化率** — 各渠道从访问到转化的效率
3. **渠道 ROI** — 如有投放成本数据：
   - CAC（获客成本）= 渠道投放 / 新客数
   - ROI = 渠道收入 / 渠道投放
   - 边际 ROI：最近一期追加投放的回报
4. **渠道质量** — 各渠道用户的留存率、复购率、LTV 差异

**用户留存分析：**
5. **留存曲线** — 次日/3日/7日/14日/30日留存率
6. **Cohort 分析** — 按注册/首购月份分组的留存矩阵
7. **留存拐点** — 留存曲线在哪天趋于平稳（找到"aha moment"时间窗口）
8. **流失原因假设** — 高流失时段对应的用户行为特征

## 约束

- 渠道对比用表格展示，按 ROI 排序
- 留存矩阵用 Cohort 表格展示
- 标注最优渠道和最差渠道
- 标注留存异常的 Cohort 并分析可能原因
- 给出渠道预算重分配建议

## 异常处理

- **precompute 出错**：降级为 `execute_python` 手动计算渠道和留存数据
- **缺少投放成本数据**：跳过 ROI 计算，仅展示渠道流量和转化率，说明"缺少成本数据，无法计算 ROI"
- **用户修改分析维度**：按用户要求重新拆分渠道或调整留存计算口径

展示结果后等待用户确认。
