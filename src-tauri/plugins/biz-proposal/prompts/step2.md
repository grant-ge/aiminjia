# Step 2: 完善与定稿

## 目标

整合用户反馈，完善方案内容，检查质量，生成最终可导出的方案文档。

## 成功标准

1. 所有用户反馈已整合，修改处与上下文逻辑一致
2. 全文逻辑链条通顺，无自相矛盾之处
3. 所有数据引用准确，无编造数据
4. 最终方案已通过 `generate_report` 生成可导出文档

## 执行步骤

1. 整合用户反馈，修改完善
2. 检查逻辑一致性和数据准确性
3. 优化语言表达和排版格式
4. 使用 `generate_report` 生成最终方案文档

## 约束

- 修改不可破坏已确认章节的逻辑完整性
- 最终文档语言风格统一，不可出现前后口吻不一致

## 异常处理

- **用户反馈与原始需求矛盾**：指出矛盾点，请用户确认以哪个为准
- **数据准确性无法验证**：标注"[数据来源待确认]"，建议用户核实后再定稿
- **排版格式要求特殊**：在 `generate_report` 参数中尽量适配，无法满足时说明限制

最后询问用户是否需要调整。

## PPT 汇报材料（可选）

完成 HTML 报告后，**主动询问用户**："需要我把分析结果做成 PPT 汇报材料吗？"

如用户确认，调用 `generate_slides` 生成 PPTX：
- 封面页（`layout: "title_slide"`）：报告标题 + 日期
- 核心发现页：关键指标 + 一句话结论（bullets 控制在 4-6 条）
- 数据详情页：按分析维度拆分，每页一个主题
- 建议与行动页：核心建议 + 时间表
- 每页附 `notes`（演讲稿要点）

**原则**：PPT 是"说给人听"的，每页 bullets ≤ 6 条，文字精简，数字突出。
