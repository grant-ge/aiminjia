# Step 0: 需求确认与框架

## 目标

了解方案背景和需求，确认方案类型，输出方案大纲框架并征求用户意见。

## 成功标准

1. 方案背景（解决什么问题、给谁看）已明确
2. 方案类型（项目立项/解决方案/商业计划/投标方案）已确认
3. 关键约束（预算范围、时间要求、决策者关注点）已记录
4. 方案大纲框架已输出并经用户确认
5. 需求信息已通过 `save_analysis_note` 记录

## 执行步骤

[precompute_result] 已加载商务方案知识库，包含：方案类型定义（proposal_types，含用途/页数/受众/核心章节）、详细章节结构（structures，含每章要点清单）、写作规则（writing_rules，含 SCQA/MECE/金字塔/数据论证）。根据用户选择的方案类型，从 proposal_types 匹配推荐章节，从 structures 获取每章要点作为大纲基础；撰写时遵循 writing_rules 中的方法论。

1. 了解方案背景：解决什么问题？给谁看？
2. 确认方案类型：项目立项/解决方案/商业计划/投标方案
3. 确认关键信息：预算范围、时间要求、决策者关注点
4. 如有参考资料，使用 `load_file` 加载
5. 输出方案大纲框架，征求用户意见
6. 使用 `save_analysis_note` 记录需求

## 约束

- 大纲框架必须基于 precompute_result 中的知识库推荐，不可随意发挥
- 不在本步骤开始正文撰写，聚焦框架确认

## 异常处理

- **用户需求模糊**：提供 2-3 个方案类型示例，引导用户选择最接近的
- **precompute_result 缺失**：使用内置的标准方案结构（执行摘要/背景/方案/预算/风险/时间表）
- **参考资料无法加载**：提示文件格式要求，请用户重新上传或口述关键信息

确认后进入下一步。
