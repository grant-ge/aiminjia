# Step 2: 客户生命周期与价值

## 目标

基于 RFM 分层，进一步分析客户生命周期阶段和长期价值，识别高风险和高潜力客户。

## 成功标准

1. 各生命周期阶段（新客/活跃/沉睡/流失）客户数和价值贡献已展示
2. 客户生命周期价值（LTV）已计算并展示统计分布
3. 高风险流失客户已标注（高价值但长时间未消费）
4. 高潜力客户已标注（新客但消费金额高）
5. 针对性的挽回和培育策略已输出

## 执行步骤

系统已自动完成生命周期与 LTV 分析，结果在 [precompute_result] 中。

**如果 [precompute_result] 有 `lifecycle_distribution`：**
- 展示各生命周期阶段分布（活跃、沉默、流失预警、已流失）
- 展示 `ltv_stats`（平均 LTV、中位数、Top 10% LTV）
- 标注流失风险比例 `churn_risk_pct`
- 对标行业基准（如有 `industry_benchmarks`）

**降级情况：**
- 使用 `execute_python` 手动计算

基于 RFM 分层，进一步分析生命周期和长期价值。

使用 `execute_python` 计算并展示：

**生命周期分析：**
1. **新客** — 首次消费在近 30 天内
2. **活跃客户** — 近期有消费且频次稳定
3. **沉睡客户** — 超过 90 天未消费但历史活跃
4. **流失客户** — 超过 180 天未消费

**价值分析：**
5. **客户生命周期价值（LTV）** — 历史总消费或预测未来价值
6. **客单价趋势** — 是否呈上升/下降趋势
7. **复购周期** — 平均多久复购一次

**输出要求：**
- 用表格展示各生命周期阶段的客户数和价值贡献
- 标注高风险流失客户（高价值但长时间未消费）
- 标注高潜力客户（新客但消费金额高）
- 给出针对性的挽回和培育策略

展示结果后等待用户确认。

## 约束

- 所有数值来自 execute_python 实际计算结果
- 生命周期阶段的天数阈值（30/90/180）可根据行业特征调整
- 不展示代码

## 异常处理

- **precompute 出错**：使用 `execute_python` 手动计算生命周期分布和 LTV
- **数据不足**：若时间跨度不足 6 个月，告知用户流失判断可能不准确，建议拉长观察窗口；若缺少复购数据，跳过复购周期分析
- **用户修改需求**：用户可要求调整生命周期阈值（如将流失从 180 天改为 120 天），按需重新计算
