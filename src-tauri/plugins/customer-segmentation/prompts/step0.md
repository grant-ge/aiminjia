# Step 0: 数据加载与探查

## 目标

加载用户上传的客户数据文件，确认数据结构和分析目标。

## 成功标准

1. 数据文件成功加载且客户数量、字段列表已确认
2. 关键字段（客户 ID、交易日期、交易金额等）已识别
3. RFM 分析可行性已评估（所需字段是否齐全）
4. 用户已确认分析目标（提升复购/识别流失/精准营销）
5. 用户需求已通过 `save_analysis_note` 记录

## 执行步骤

用户已上传客户数据文件。系统已自动识别数据结构，结果在 [precompute_result] 中。

**如果 [precompute_result] 存在且有效：**
- 直接展示识别结果（客户ID字段、金额字段、时间字段、RFM可行性）
- 向用户确认分析目标

**如果 [precompute_result] 不存在或出错：**
1. 使用 `load_file` 加载文件
2. 使用 `execute_python` 快速探查数据结构：
   - 客户数量、字段列表
   - 关键字段：客户 ID、交易日期、交易金额、交易次数等
   - 时间范围
   - 缺失值情况

3. 向用户确认：
   - 数据是否正确加载
   - 分析目标（提升复购/识别流失风险/精准营销）
   - 是否有特定的客户群体需要重点关注

4. 使用 `save_analysis_note` 记录用户需求

**输出格式示例：**
```
已加载客户数据，共 5,678 位客户，交易记录时间范围 2024-01 至 2025-12。

数据字段：
- 客户 ID、交易日期、交易金额、产品类别、渠道来源

请问你的分析目标是什么？
1. 识别高价值客户，制定 VIP 策略
2. 发现流失风险客户，制定挽回计划
3. 全面分层，制定差异化运营策略
```

确认后进入下一步。

## 约束

- 不对数据做任何假设，所有字段含义需从数据本身推断或向用户确认
- 不展示代码

## 异常处理

- **precompute 出错**：回退到手动加载流程，使用 `load_file` + `execute_python`
- **数据不足**：若客户数 < 10 或缺少客户 ID 字段，告知用户数据不足以支撑客户分层分析，建议补充
- **用户修改需求**：用户可随时调整分析目标，重新记录需求后继续
