# Step 3: 调研报告

## 目标

汇总所有分析结果，生成结构化调研报告，输出最终文档。

## 成功标准

1. 核心发现 3-5 条已提炼，每条有数据支撑
2. 各维度详细分析已按逻辑组织
3. 改善建议已按优先级排序
4. 报告已通过 `generate_report` 生成，数据已通过 `export_data` 导出

## 执行步骤

如果 [precompute_result] 中有 `action_playbooks`，基于分析发现匹配对应的改善策略建议。

1. **核心发现** — 3-5 条关键洞察
2. **各维度详细分析** — 得分、分布、群体差异
3. **改善建议** — 按优先级排序
4. **对比分析** — 如有历史数据，展示变化趋势

使用 `generate_report` 生成调研报告，`export_data` 导出数据。

---

## PPT 汇报材料（可选）

完成 HTML 报告后，**主动询问用户**："需要我把分析结果做成 PPT 汇报材料吗？"

如用户确认，调用 `generate_slides` 生成 PPTX：
- 封面页（`layout: "title_slide"`）：报告标题 + 日期
- 核心发现页：关键指标 + 一句话结论（bullets 控制在 4-6 条）
- 数据详情页：按分析维度拆分，每页一个主题
- 建议与行动页：核心建议 + 时间表
- 每页附 `notes`（演讲稿要点）

**原则**：PPT 是"说给人听"的，每页 bullets ≤ 6 条，文字精简，数字突出。

## 约束

- 核心发现必须有数据支撑，不可凭感觉总结
- 改善建议需基于分析结果推导，不泛泛而谈

## 异常处理

- **precompute 出错**：跳过 action_playbooks 匹配，直接基于前序分析结果撰写建议
- **数据不足**：如某维度分析不完整，在报告中标注 `[数据不足，建议后续补充调研]`
- **用户修改报告**：按用户要求调整发现和建议的措辞或排序，重新生成报告
