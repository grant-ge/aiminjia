=== 当前任务：Step 2 — 逐条合规审查 ===

## 目标

对 Step 1 结构化的每一条款进行合规性审查，按风险等级分类标注，并完成制定程序合规评估。

## 成功标准

1. 每一条款均完成合规性审查并归入 🔴/🟡/🟢 分类
2. 🔴 条款均引用了具体法律条文（法律名称 + 条款号）
3. 缺失条款清单完整且标注严重程度
4. 制定程序合规评估完成（基于 Step 0 收集的信息）
5. 汇总统计数据准确

## 执行步骤

对 Step 1 结构化的每一条款进行合规性审查：

1. **🔴 无效/违法条款**：
   - 指出原文条款内容
   - 说明违反的具体法律条文（法律名称 + 条款号）
   - 引用典型案例或司法实践作为参考
   - 给出修改方向

2. **🟡 有争议/有风险条款**：
   - 指出风险点
   - 说明各地司法实践的差异
   - 给出风险规避建议

3. **🟢 合规可优化条款**：
   - 指出可完善之处
   - 给出优化建议

4. **缺失条款检查**：
   - 对照制度类型应有的标准条款清单
   - 列出应有而未规定的重要条款
   - 标注缺失的严重程度

5. **制定程序合规评估**：
   - 根据用户提供的程序信息，评估是否满足《劳动合同法》第4条要求
   - 程序瑕疵对制度效力的影响分析

6. **汇总统计**：
   - 🔴 无效/违法 X 条
   - 🟡 有争议/有风险 X 条
   - 🟢 合规可优化 X 条
   - 缺失条款 X 项

如需查询最新司法解释或地方规定，可使用 `web_search`。
使用 `save_analysis_note` 保存审查结果。

展示审查结果后等待用户确认。

## 约束

- 审查须覆盖 Step 1 中的每一条款，不可遗漏
- 法律条文引用须准确，不可编造不存在的法条
- 区分"法定要求"和"最佳实践建议"，不可将建议性内容表述为强制要求
- 制定程序评估须基于 Step 0 收集的实际信息，未提供的标注"待确认"

## 异常处理

- Step 0 未收集到制定程序信息：制定程序评估部分标注"用户未提供程序信息，无法评估，建议补充"
- 条款涉及地方性法规差异：列出主要地区（如北京、上海、广东）的不同实践，建议用户确认所在地规定
- 遇到新型条款（如远程办公、AI 使用规范）：标注"现行法律未明确规定"，给出合理性分析和风险提示
