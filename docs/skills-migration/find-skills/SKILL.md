# find-skills

你是 AIjia 的技能发现与安装编排技能。你的任务不是直接完成用户业务，而是在当前已启用技能不够用时，先从企业技能市场发现更合适的专用技能，再按搜索结果决定是否安装并激活。

## 核心原则

先判断当前 catalog，再搜索市场。已启用技能明显覆盖任务时，直接 `Skill(skill_id=...)`，不要使用本技能。

不要把普通公开网页任务误判为市场技能发现。用户只是打开普通网站、读取公开页面标题、抓取公开网页内容时，优先使用已有 `browser` 或通用能力。

不要为了“试试看”安装技能。安装只在候选明确、置信度足够、且符合用户任务时发生。

## 触发范围

使用本技能：

- 当前 catalog 没有明显可用技能覆盖用户任务。
- 用户要处理企业/业务系统、企业工具连接、专业分析、业务明细/日志数据、特殊文件流程或领域自动化。
- 用户问“能不能做 X / 怎么做 X”，且 X 看起来可能有专用技能。
- 用户明确要求找、安装、发现、扩展技能。

不要使用本技能：

- 闲聊、简单事实查询、常识问答。
- 已启用技能已经明确覆盖任务。
- 普通公开网页读取、页面标题抓取、普通网站浏览。
- 只需要当前 shell、文件或浏览器通用能力即可完成的简单任务。
- 本地已安装技能的搜索：本地技能已经在 catalog 中。

## 搜索准备

1. 保留用户原始任务作为 `task`，不要改写成泛泛关键词。
2. 抽取最多 5 个 `capabilityHints`。优先从用户原始任务中提取短词或短语：
   - 业务系统名、产品名、平台名。
   - 业务对象、单据、流程、指标、文件类型、日志类型。
   - 用户明确提到的分析目标、动作或产出。
3. 不要把多个同义词拼成一个长字符串。
4. 不要维护固定能力清单；不要为了凑数填泛化词。
5. 不要把具名业务系统泛化成 `browser_automation` 或 `web_scraping`。
6. 只有用户明确是在处理普通公开网页时，才使用 `browser_automation` 或 `web_scraping`。

具体产品名、别名、错别字和技能 ID 不要写进本技能正文。它们应沉淀到每个市场技能自己的名称、描述、`when_to_use`，或后续扩展的别名/关键词元数据中，再由搜索工具读取和排序。

## 标准流程

1. 调用 `SkillMarketSearch`：
   - `task`: 用户原始任务。
   - `capabilityHints`: 从任务中抽取的少量能力提示。
   - `maxResults`: 默认即可，除非确实需要更多候选。
2. 根据搜索状态处理：
   - `requires_find_skills`: 说明你未按顺序调用；立即重新按本流程执行。
   - `already_installed`: 调用 `Skill(skill_id=installedSkillId)`，再继续处理用户原任务。
   - `installed_disabled`: 不要重新安装，不要绕过关闭状态；简短说明该技能当前关闭。
   - `no_match`: 不安装任何技能，说明未找到合适技能，然后再考虑用现有能力继续或询问用户。
   - `matched`: 只有一个候选时继续看置信度和理由。
   - `needs_choice`: 必须调用 `AskUserQuestion` 让用户选择，不要直接安装第一名。
3. 安装决策：
   - 只有一个候选、`confidence == "high"`、且理由明显匹配用户任务时，可以调用 `SkillMarketInstall`。
   - 候选为 medium/low、多个候选接近、或你无法判断时，先用 `AskUserQuestion` 让用户选择。
   - 一次只安装一个技能，除非用户明确要求多个。
4. 安装成功后，必须立即调用 `Skill(skill_id=<installed skillId>)` 读取新技能指令，再继续用户原任务。

## 向用户确认

需要选择或确认时，使用 `AskUserQuestion`。选项只展示少量高相关候选，包含技能名、简短描述和为什么匹配。不要把市场全量结果复述给用户。

高置信单候选可以直接安装；其他情况先问用户。

## 禁止事项

- 不要搜索本地已安装技能。
- 不要安装低置信或无关技能试错。
- 不要绕过用户关闭状态重新安装同名技能。
- 不要把普通网页任务都送去市场。
- 不要在本技能里维护具体产品到技能 ID 的长映射表。
- 不要要求用户先说“找技能”；应根据任务本身判断是否需要市场技能。
