# Skill-First 工作台视觉改版 — 设计规格

> **状态**：设计（视觉稿阶段）
> **日期**：2026-04-21
> **作者**：oayzz + Claude Code
> **范围**：前端信息架构 + 视觉规范 + 各页面视觉稿；**不含**后端/Runtime 改动；**不含**实现计划。
> **产物**：`design.pen`（Pencil 绘制的视觉稿）+ 本 spec。

## 1. 背景与目标

### 1.1 现状痛点

- 产品里的「角色（Persona）」强耦合 Onboarding 与侧栏：新用户必须先选身份、切身份才能换对应技能集。实际上用户心智里"按技能分类挑能力"更轻，切身份是伪需求。
- 技能能力被藏进「设置 → 技能」两级路径，发现成本高；市场页与已安装列表拼在一个 Tab 里，既是发现入口又是管理入口。
- 首页欠缺"开箱即用"的灵感起点：Welcome 页只有一个空输入框。
- 本地模型 / 云端模型的双线让侧栏底部的切换按钮成为常态负担，实际业务方向只保留云端登录账号。
- 无定时任务 / 无技能详情页，但产品规划已经需要。

### 1.2 本次目标

1. 删除角色概念，把原「角色」改造成**技能中心的分类维度**；原 personas 数据作为各分类下的「默认技能」。
2. 提出 Skill-First 的四栏工作台信息架构：**新任务 / 技能中心 / 定时任务 / 设置**。
3. 对齐参考图的亮色视觉语言：米白底 + 大圆角卡 + 主色 `#DBAA22` + 辅助色 `#143290`。
4. 在 `design.pen` 中按「通用组件 → 整页」的顺序产出覆盖 8 屏的视觉稿。
5. 移除本地模型路径，登录是强制门槛；退出登录回到登录页。

### 1.3 非目标

- 不改 Rust runtime / Python runtime / tool pipeline 等后端结构。
- 不画 dark 主题（产品采用启动时下发的单主题，不做深浅模式切换）。
- 不画 BrowserPanel（当前对话页的右侧浏览器栏）——作为能力保留，但本轮视觉稿不体现。
- 不画 Onboarding / 欢迎页——登录即唯一首屏拦截。
- 不出实现计划（交给 writing-plans 阶段）。

## 2. 信息架构

### 2.1 侧栏主导航（4 入口）

```
┌──────────────┐
│  [Tenant ▾]  │  顶部租户切换器（保留现有能力）
│  ── 主导航 ─ │
│  ✨ 新任务    │  ← 首页（默认）
│  🧩 技能中心  │
│  ⏰ 定时任务  │
│  ── 任务区 ─ │
│  默认项目 ▾  │  conversations grouped
│    · 对话 1  │
│    · 对话 2  │
│  ⚙ 设置      │  底部
└──────────────┘
```

- 侧栏本身保留"会话历史列表"区域（按时间段/项目分组），与当前实现一致。
- 删除：侧栏顶部的 **Persona 切换器**（整块去掉）。
- 删除：侧栏底部的 **云端/本地 toggle**（本地模型路径去除）。
- 保留：设置按钮（底部）；`+ 新任务`按钮（切换到「新任务」主视图 = 新建对话 or 回首页）。

### 2.2 主视图路由

| 侧栏入口 | 主视图内容 |
|---|---|
| 新任务 | 首页（大输入框 + 分类 Tab + 推荐提示词） |
| 技能中心 | 技能列表页 → 技能详情页 |
| 定时任务 | 定时任务页（推荐模板 + 已定时任务表） |
| 对话项（任务区点击） | 对话页 |
| 设置（底部） | 设置大号 Modal |

### 2.3 技能体系

- **分类**（一级维度，和原 personas 对齐）：通用工具、电商、门店与财务、设计与制造、开发、律所、媒介、健康与学习、运营、内容创作 10 个；外加"为你推荐"作为动态分组（不是真分类）。
- **技能**（二级实体）：原 personas 数据全部作为各分类下的"默认技能"落地（不走下载流程，默认已安装）。用户额外从技能中心下载的技能叠加其上。
- **安装/卸载**：入口集中在技能中心。对话页的技能弹层**只展示已安装**，带"去技能中心"入口。

### 2.4 登录与退出

- **未登录** → 强制显示登录页（居中登录卡，账号+密码）。
- **已登录** → 进入 App 主界面。
- **退出登录** → 回登录页。
- 删除本地模型路径：移除 `useCloud` 状态、侧栏的 local/cloud 切换按钮、设置里不再有本地模型开关。模型来源固定为云端。

## 3. 视觉规范

### 3.1 主题令牌（覆盖本次）

Pencil 变量（`design.pen` 已定义 dark/light 两套，本轮稿只画 light，并把主色/辅助色对齐）：

| Token | 值 | 用途 |
|---|---|---|
| `--accent-primary` | `#DBAA22` | 主色：主按钮、选中态、焦点环、活跃 Tab 下划线 |
| `--accent-secondary` | `#143290` | 辅助色：次要强调、深蓝文字、链接 hover |
| `--bg-page` | `#FFFFFF` | 主内容区底 |
| `--bg-sidebar` | `#F6F4EE` | 侧栏底（暖白） |
| `--bg-surface` | `#F6F8FA` | 输入框/次级卡片底 |
| `--bg-input` | `#F0F2F5` | Input / chip 底 |
| `--border-primary` | `#E1E4E8` | 主分隔线 |
| `--border-secondary` | `#D0D7DE` | 次级分隔线 |
| `--text-primary` | `#1F2328` | 主要正文 |
| `--text-secondary` | `#656D76` | 次要正文 |
| `--text-tertiary` | `#8C959F` | 辅助信息 |
| `--text-muted` | `#AFB8C1` | 占位/禁用 |
| `--accent-success` | `#16A34A` | 成功/已连接徽标 |
| `--accent-warning` | `#D97706` | 警示 |
| `--accent-error` | `#DC2626` | 错误 |

> 说明：首屏稿里产品名显示为 "AI小家"（面向用户），app.md 元数据仍为 "AIjia"。本轮视觉稿里品牌文字使用"AI小家"。

### 3.2 基础规范

- **圆角**：容器 12、大卡 16、胶囊按钮 999。
- **阴影**：弹窗 `0 8px 24px rgba(0,0,0,0.08)`；hover 卡片 `0 2px 6px rgba(0,0,0,0.05)`。
- **间距栅格**：4 基，常用 8/12/16/24/32。
- **字号**：H1 22 / H2 18 / H3 15 Medium / Body 14 / Caption 12 / Label 11。
- **字体**：系统默认（.AppleSystemUIFont / PingFang SC）。
- **图标**：沿用 shadcn 图标风格（lucide 单色描边）。

## 7. 验收

- `design.pen` 含"组件画板"（含第 4 节全部自定义组件）+ 第 5 节列出的 9 张页面稿。
- 色彩沿本 spec 第 3 节 token；主色 `#DBAA22`、辅助色 `#143290`。
- 画板顺序：组件画板 → 登录 → 新任务 → 技能中心 → 技能详情 → 定时任务 → 对话（默认/弹层/执行中）→ 设置 Modal 总览 + 各 Tab 分块。
- 命名可被后续前端实现阶段直接引用为 React 组件名。
