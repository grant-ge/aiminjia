## 跑测中的副发现（非 CLI gap，记此处）

### messages.jsonl 不是严格 ndjson

意图 3 跑测期间尝试用 `python json.loads` / `jq` 解析 `messages.jsonl` 失败。原因：`content.text` 内的真实换行符 `\n`（hex `0a`）没被 JSON-escape 成 `\\n`，导致：

- 单条 user 消息被换行符拆成多段，`wc -l` 数到的虚高
- 任何 strict JSON 解析（python / jq / Node JSON.parse）都报错
- 只有 lotus-app 自己的非严格 parser 能读

真正的记录分隔符是 `\t✓\n`（runner skill §5.7 已记录"末尾 \t✓ 校验位"，但没说"`\n` 在 text 字段内不转义"）。

**临时绕路（agent 跑测用）**：

```python
import re, json
content = open(MSG_PATH).read()
records = [p for p in content.split('\t✓\n') if p.strip()]
for raw in records:
    fixed = re.sub(r'(?<="text":")([^"]*?)(?=")',
                   lambda m: m.group(1).replace('\n','\\n').replace('\r','\\r'),
                   raw)
    d = json.loads(fixed)
```

**判定**：rules.md 数字员工意图 3 写"`messages.0.jsonl` 第 1 行"的"行"措辞，按字面跑会判错（被换行拆分的第一段不是第 1 条 user）。建议 author 改 rules："第 1 条记录"+ 明确按 `\t✓\n` 分隔；产品方决定是否修存储格式（serde_json 严格 escape）。

### Webview 偶发白屏（reload 可恢复）

意图 4 跑测期间 webview 出现 `#root` 内 children=0（React 不渲染），整个 UI 空白。`tauri-pilot navigate http://127.0.0.1:5173/` reload 之后恢复。后端 chat / store 数据完整，应该是 HMR 或某次 layout shift 把 React 树清了。不是数字员工 task 的产品 bug，只是跑测过程中的 quirk。

### rules.md 数字员工意图 3 路径写错

写 `~/.renlijia/conversations/{convId}/messages.0.jsonl`，实际：

1. 老路径 `~/.renlijia/conversations/`（已迁移），新路径 `~/.renlijia/users/{scope}/conversations/`
2. 文件名 `messages.jsonl`（无 `.0`）
