## 3. 修复了的 5 处产品缺陷（全部 commit `d8925b51 feat(artifact)` 引入，作者 pzc + Qoder 生成）

### bug #1 — `src/hooks/useTurnRenderModel.ts` 编译失败（已修）

Qoder 生成 diff 时把 `function formatFileSize(bytes: number | undefined): string | null {` 这一行替换成了注释 `// ── File size & metadata formatting ──`，但函数体 4 行没动 → 孤儿函数体。esbuild 报 `Unexpected "}"` at L169。

**Fix**：补回函数签名。

### bug #2 — `src/hooks/useTurnRenderModel.ts` 残留 git conflict markers（已修）

Qoder commit 里挂着 `<<<<<<< HEAD` / `=======` / `>>>>>>> f0b23570 (feat(artifact): ...)` 三行 marker（L497 / L531 / L532）。HEAD 段是新加的 artifact 渲染代码，`=======` 跟 `>>>>>>>` 之间是空（Qoder 把 clean addition 错标成 conflict）。

**Fix**：删 3 行 marker，保留 HEAD 段（artifact 解析 + 渲染分支）。

### bug #3 — `useTurnRenderModel.ts` L426 旧路径 + L497 新路径双 push（已修）

`if (m.role === 'assistant')` 分支下：L426-L430 旧路径直接 push raw `m.content.text`（含 `![artifact](`），L497-L530 新路径 push 剥离后 cleanedText。两段都跑 → 每条 assistant message 入 `aiSegments` 两次、`blocks` 两个 `assistantText` block → DOM 渲染原始 mark + 剥离后两份。

**Fix**：合并 L497 逻辑进 L426 原位置（在 toolCalls 处理之前，符合原本"text first then tools"顺序），删 L497-L530。

### bug #4 — 卡片「用 X 打开」/「在文件夹中显示」失败（已修）

`MessageList.tsx` 的 `handleOpenExternal` / `handleReveal` 调 `openGeneratedFile(file.id, convId)` / `revealFileInFolder(file.id, convId)`。这俩后端 IPC 用 `resolve_stored_path(db, file_id, conv_id)` 按 id 查 db。但 artifact 路径的 `file.id` 是合成的 `artifact-${m.id}-${f.fileName}`、**后端 db 里没注册** → IPC 报错 → 前端 toast `打开生成文件失败` / `定位生成文件失败`。

**Fix**：MessageList handler 判 `file.id.startsWith('artifact-')` 时绕过 IPC，走 `@tauri-apps/plugin-shell.open(filePath)`。reveal 走 `open(parentDir)`（plugin-shell 无 reveal API、退而求其次开父目录）。同步给 `RenderGeneratedFile` 加 `filePath?: string`，`normalizeGeneratedFile` 透传。

### bug #5 — 卡片「预览」也失败（已修，2026-06-02 用户截图发现）

`handlePreview` → `openPreview(toPreviewTarget(file, convId))` → `FilePreviewPane` 用 `targetFileId + targetConversationId` 调 `getFilePreview(id, convId)` IPC，同样不识别 artifact 合成 id → reject → toast `无法预览此文件`。

`FilePreviewPane` 本身已支持 `targetLocalPath` 分支调 `getLocalFilePreview(path)`（避后端 IPC），`PreviewTarget` 接口也已经定义了 `localPath?: string` —— 只是 `toPreviewTarget` 没传。

**Fix**：`generatedFileActions.ts` 的 `toPreviewTarget` 判 `file.id.startsWith('artifact-')` 时设 `localPath: file.filePath`；`GeneratedFileActionSource` 加 `filePath?: string` 字段。
