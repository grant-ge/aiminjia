# rules.md — masking-level 传递链路测试意图

验证方式：**agent 跑**（启动真实应用，在设置界面切换脱敏级别后发消息，观察 AI 回复和磁盘记录）

存储路径速查：
```
~/.renlijia/
└── users/{scope}/conversations/{conv_id}/
    └── messages.jsonl   # 每行一条消息，role / content.text
```

scope 格式为 `t_{tenantId}__u_{userId}`，可从 `~/.renlijia/users/` 目录名获取。

---

## 意图 1：宽松脱敏下，发给 AI 的消息内容不包含占位符

**场景**
用户在设置中将数据脱敏级别调为「宽松」后发送含身份证号的消息，AI 回复中不应出现任何 `[ID_CARD_*]` 格式占位符。

**前提**
- 应用已启动并登录
- 在「设置 → 隐私 → 数据脱敏」中将级别设置为「宽松」
- 新建对话，记录该对话的 conv_id

**操作**
1. 在输入框输入 `"我的身份证号是 110101199001011234，帮我确认一下格式是否正确"`，点击发送
2. 等待 AI 完整回复

**验收标准**
- AI 回复中不包含 `[ID_CARD_1]` 或任何 `[ID_CARD_*]` 格式字符串
- AI 回复中包含数字 `110101199001011234` 或对该号码格式的直接评价（说明 AI 收到了未脱敏的原文）
- `messages.jsonl` 存在，文件共 2 行，每行均为合法 JSON
- 第 2 行 `role` 字段值为 `"assistant"`，`content.text` 不为空

---

## 意图 2：严格脱敏下，身份证号、手机号、邮箱均被替换为占位符

**场景**
用户在设置中将数据脱敏级别调为「严格」后发送含多类 PII 的消息，AI 回复应基于脱敏后的��位符内容，原始 PII 不出现在 AI 收到的消息中。

**前提**
- 在「设置 → 隐私 → 数据脱敏」中将级别设置为「严格」
- 新建对话，记录 conv_id

**操作**
1. 在输入框输入以下消息并发送：
   `"请帮我整理这些信息：身份证 110101199001011234，手机 13800138000，邮箱 test@example.com"`
2. 等待 AI 完整回复

**验收标准**
- AI 回复中不包含 `110101199001011234`（原始身份证号）
- AI 回复中不包含 `13800138000`（原始手机号）
- AI 回复中不包含 `test@example.com`（原始邮箱）
- AI 回复中包含 `[ID_CARD_1]`、`[PHONE_1]`、`[EMAIL_1]` 中的至少一个占位符格式（说明脱敏正常生效）
- `messages.jsonl` 存在，文件共 2 行，每行均为合法 JSON

---

## 意图 3：脱敏级别为空或未知值时，系统回退严格脱敏

**场景**
当存储中的脱敏级别字段为空字符串或未知值时，系统应默认使用严格脱敏，不因字段异常而跳过 PII 处理。

**前提**
- 应用已关闭
- 找到当前用户的 global settings 文件（路径为 `~/.renlijia/settings.json` 或通过 `multica` 工具确认路径）
- 备份原文件：`cp ~/.renlijia/settings.json /tmp/settings_bak.json`
- 将文件中的 `data_masking_level` 字段值改为空字符串 `""`（若字段不存在则手动添加）
- 重新启动应用并登录

**操作**
1. 新建对话，记录 conv_id
2. 在输入框输入 `"我的身份证是 110101199001011234"` 并发送
3. 等待 AI 完整回复
4. 测试完毕后恢复：`cp /tmp/settings_bak.json ~/.renlijia/settings.json`

**验收标准**
- AI 回复中不包含 `110101199001011234`（说明空值回退到了严格脱敏）
- AI 回复中包含 `[ID_CARD_1]` 占位符
- `messages.jsonl` 存在，文件共 2 行，每行均为合法 JSON

---

## 意图 4：同一对话多轮发消息，脱敏级别全程保持一致

**场景**
一次对话从发第一条消息到第三条消息，脱敏级别应在整个 turn 周期内保持快照状态不变，不因中途有工具调用而重新读取设置。

**前提**
- 在「设置 → 隐私 → 数据脱敏」中将级别设置为「严格」
- 新建对话，记录 conv_id

**操作**
1. 发送消息：`"第一条，我的手机是 13800138000"`，等待完整回复
2. 发送消息：`"第二条，我的邮箱是 test@example.com"`，等待完整回复
3. 发送消息：`"第三条，我的身份证是 330101199001011234"`，等待完整回复
4. 读取 `~/.renlijia/users/{scope}/conversations/{conv_id}/messages.jsonl` 的全部内容

**验收标准**
- 三轮 AI 回复中均不包含原始手机号 `13800138000`、邮箱 `test@example.com`、身份证号 `330101199001011234`
- 三轮 AI 回复中均出现对应的占位符格式（如 `[PHONE_1]`、`[EMAIL_1]`、`[ID_CARD_1]`）
- `messages.jsonl` 共 6 行（3 条 user + 3 条 assistant），每行均为合法 JSON
- 所有 assistant 行的 `content.text` 不为空
